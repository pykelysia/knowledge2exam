# 试卷生成工具

本产品聚焦于教育领域，主要服务于学生。前端负责用户交互与内容上传，后端向前端提供试卷生成等服务。

## 前端内容

用户会从前端上传包括但不限于以下几种内容或形式的附件和文字（并非全部必须，但至少要有一项）

- 从内容上：
  - 课程使用的书籍资料
  - 教师的授课 ppt 或 pdf 等用于授课的文件
  - 多方途径获取的重点知识点清单
  - 多方途径获取到的往期试卷
  - 用户自己的学习笔记
  - 用户的额外要求
- 从形式上：
  - 包括 docx、ppt、pdf、md等在内的主流文档格式
  - 包括 jpg、png、jpeg等在内的主流静态图片格式（不包含类似 gif 在内的动态图片）
  - 包括用户的手动输入的文本内容

以上内容用户可以选择哪些内容可以共享，选择共享后将会将对应的资源在审核过后存入对应学校和课程的知识库（用户手动输入的内容不能也不应该有共享选项）。

用户在使用前还可以选择是否需要为每道题生成答案解析：若选择需要，则后续出题阶段生成的每道题都会附带解析内容；若不选择，则不生成解析。

## 后端的预处理阶段

该阶段针对不同的内容应当处理至不同的程度。

书籍资料、教师授课使用内容、用户笔记应当进行切块向量化然后存入对应的向量数据库。

重点清单、和用户额外要求放置在用户提示词中。若该内容长度过长，应先检测长度，超出阈值时触发压缩 agent 对其进行基于语义的压缩，再放入提示词，避免上下文超限。

往期试卷应保存在文件中并在内存中保留尽可能方便读取的存储，在规划和出题阶段需要时常查看。

然后对于用户选择共享的内容应该在对应的学校及课程下将预处理的内容同时保存。但在此之前应当进行内容安全检测（自动检测，非人工审核），检测通过后才允许存入共享知识库；检测不通过则不予收录。

同样的，对于共享库中存在的内容也应当划入本次生成的可用知识库中，但不同类型的内容采用不同的取用策略：

- **排他类（重点清单、往期试卷）**：若用户本次已提供该类内容，则只使用用户提供的部分，不再引入共享库中的同类内容。因为这两类代表用户本次明确希望聚焦的范围，不应被其他来源干扰；若用户未提供，则使用共享库中同校同课程的同类内容。
- **叠加类（书籍资料、教师授课内容、用户笔记）**：无论用户本次是否提供，都会同时叠加使用共享库中同校同课程的已有内容。因为共享库中可能存在用户未上传、但在本次考察范围中占相当比例的内容。

## Agent 生成阶段

### 主agent规划阶段

如果用户提供了往期试卷，则应该在较大程度上以往期试卷为参考进行改变，不同题型的占比不能发生超过 10% 的相对变动（例如某题型原占比 30%，允许调整范围为 27%~33%，而非增减 10 个百分点；这样可以避免占比本身较小的题型被大幅压缩甚至消失），题目内容应当作出改变，不能将原题原封不动的搬上来，唯一例外见"子agent出题阶段"中关于概念性填空题的说明。

如果用户未提供往期试卷，则优先查看是否存在已共享的相同学校相同课程的往期试卷。若存在则将其作为参考同上段处理；若不存在则按照 20%选择题 20%填空题 60%简答题的基本模板出题。

然后再规划阶段，应该有一个功能较强大的模型驱动的 agent 来进行策划，参考往期试卷（如果有；若存在多份应当综合参考取其较大共同点，具体包括题型分布、知识点覆盖、难度分配三个维度）和重点清单（如果有；若用户已提供则不应当参考其他来源的重点清单，若用户未提供则应该尽可能多的参考其他来源的重点清单）。

这一步需要注意以下要求：

- 设计每道题应该给出涉及的知识点内容、对应的题型、难度。这些信息仅在规划阶段内部使用，不作为出题 tool 的独立字段传递，而是隐式保存在最终生成的 md 文件中。
- 注意应该将重点对应的考察方向一并写明。
- 如果这道题的规划有对往期试卷或书籍资料或教师授课内容或用户笔记较强的参考性质，应当同步注明参考来源，供子agent判断该题能否直接沿用或轻改。保留适当部分简单常见考题只是这一机制带来的副产品之一，而非唯一目的。
- 同一重点的相同/相似考察方向不能出现超过两次，由主agent基于自身对题目内容的语义理解进行自查判定，不依赖额外的向量相似度等基础设施。

然后将出题任务调用给子agent 进行具体题目的生成。选择题和填空题各有一个agent来负责全部的相同题型，而简答题则应该每一个题交由一个单独的 agent 完成。

### 子agent出题阶段

首先收到主agent的任务之后应该先检索这一任务需要用到的所有知识点。

如果任务中提及了参考来源，应当将参考来源同步引入。若该参考来源仅为简单题，如单纯计算题，或概念性填空题，则不应该做太大改动，计算题应仅修改数值即可，而概念性填空题（如对某现象的解释类题目）允许原封不动迁移——这是"不能将原题原封不动搬上来"这一原则的唯一例外。

出题应该通过 tool 调用来实现，包括三种 tool （选择，填空，简答），若用户选择需要答案解析则各 tool 额外附带解析字段：

- 选择：题目，ABCD依次四个选项内容，正确答案（可选：解析）
- 填空：题目、正确答案（可选：解析）
- 简答：题目、子问题（可选）、正确答案、子问题答案（可选）（问题和答案的调用顺序应当相互对应）（可选：解析）

若某道题因非语法错误问题（如内容偏差、违规内容等）连续重新生成超过 3 次仍不通过，子agent不再继续重试，而是向主agent申请更换本题的出题内容（如更换知识点或考察方向）。

### 审查阶段

> 可选内容，由用户决定是否启用

这一阶段主要检查子agent出题阶段的成果是否符合要求，主要关注以下内容：

1. 是否出现违规内容。（如政治敏感，在知识库中并未明确提及相关的政治内容；或出现色情等内容）
2. 题目内容于主agent 的规划出现超过20%的偏差
3. 题目中若出现 latex 等语法的公式，是否出现md无法渲染的现象

上述内容中若出现前两者则要求子 agent重新生成（该重试计入子agent出题阶段所述的3次上限），若出现第三个情况则在审查阶段直接修改至正确即可，不计入重试次数。

## 后端的后处理阶段

将agent生成输出的内容以md格式整合到一个文件内，并将其渲染到 pdf 格式并返回给用户。
