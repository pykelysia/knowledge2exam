# PDF Analyzer

## 类型检测

将 pdf 分成三种类型

- 纯文本 PDF (文本层为主，且文本层文本可以直接提取，版面排版较规则)
- 扫描件 PDF (以图片为主要内容，文本层缺失或无法直接使用)
- 混合型 PDF (同时包含文本，图片，图表等内容，单靠文本层无法完整表达语义)

根据不同的类型进入不同的处理层。

## 处理方法

### 纯文本 PDF

直接抽取文本层，保留章节结构、页码、段落边界、表格/图片引用。

### 扫描件 PDF

将页面转为图片，然后进行图像增强处理，进入 OCR 识别，然后进行版面分析使阅读顺序恢复

### 混合型 PDF

将页面按区域切分，分为

- 文本区
- 表格区
- 图表区
- 图片区

分别送入不同的解析链路，多模态类型的区域要与周边的上下文融合

上面三种pdf进入知识库都要经过 chunk embedding 的过程进入向量数据库

## 实现映射

| 模块 | 职责 |
|---|---|
| `app/ingestion/pdf_layout.py` | 类型检测（`classify_document`）+ 区域切分（文本块/表格/图片/矢量图表簇单遍收集）+ 标题结构（TOC 优先，无目录时字号启发式） |
| `app/ingestion/image_enhance.py` | 扫描件图像增强（灰度 → 自动对比度 → 轻锐化，失败回退原图） |
| `app/ingestion/parsers/pdf.py` | 三路路由与正文组装（`PyMuPDFParser`），纯文本结构化抽取 / 扫描件整页栅格化 / 混合型按阅读顺序区域组装 |
| `app/ingestion/ocr.py` | 视觉 LLM：整页转录（扫描件/坏页）、图片文字转写（图片区）、图表描述（图表区，独立提示词） |
| `app/ingestion/postprocess.py` | 图片 OCR 后处理（预筛选/去重/合并）+ `inline_image_text` 占位符就地融合 + `replace_page_text` 整页替换 |
| `app/ingestion/chunking.py` | `chunk_pdf`：按 `--- Page N ---` 标记把页码写入 `chunk.page`，页界即块界 |
| `app/orchestration/stages.py` | 编排接线：OCR 替换 → 图片融合（占位符回填，无占位符回退文末追加）→ chunk → embedding → pgvector |

### 类型判定规则

- 扫描页：页级体检不通过（`no_text`/`garbled`）且图片覆盖率 ≥ 0.5
- 扫描件：扫描页占比 ≥ 0.9
- 混合型：任一页存在显著视觉内容（图片覆盖率 ≥ 0.15，或检出表格/矢量图表簇）
- 纯文本：其余情况；个别乱码页仍由页级体检兜底走整页 OCR
- 特例：健康页 + 整页大图（覆盖率 ≥ 0.7）+ 足量文本（≥ 120 字符）视为"扫描后带隐藏文本层"，以文本层为准、跳过内嵌图片提取

### 上下文融合

混合型/纯文本链路中，图片区与图表区在正文中以占位符（`[图: p3-1]` / `[图表: p3-1]`）
标记原文位置；视觉 OCR 完成后由 `inline_image_text` 就地替换为引用块（`> 图：…` /
`> 图表：…`），实现"多模态区域与周边上下文融合"。已被整页 OCR 覆盖的页跳过内嵌图片
识别，避免内容重复。

### 配置项

- `pdf_ocr_mode`：`auto`（按类型与页体检路由，默认）/ `off` / `always`
- `pdf_scan_enhance`：扫描页图像增强开关（默认开）
- `ocr_dpi` / `ocr_max_pages`：栅格化 DPI 与单任务 OCR 页数上限（沿用原有配置）
